# 采购模型审查阶段验证

2026-11-15，Windows、Python 3.12。

采购入口现已调用 MiniHermes 的 run_loop 和采购专用 ToolRegistry。工具仅返回后端绑定的当前申请、
版本化制度与本部门同类已办结案例。模型提交结构化材料、逐字段原文摘录及引用编号，
后端校验引用和原文存在性，再运行确定性规则重算费用。负责人核对建议并最终决定与发信。

SQLite 保存原邮件和审查任务。模型调用不持有数据库写事务，晚到结果与当前申请版本不符时丢弃。
审查完成会更新申请版本，旧表单不得批准模型运行后才更新的材料。
生产收信和页面要求当前版本审查成功；低层存储接口保留离线兼容选项。

## 真实模型验收

复用原邮箱工程已配置的 glm-4.5-air，通过既有 OpenAI 兼容适配调用，材料全部虚构。
输入为「申请订阅设计软件用于出图，需要5个席位，订阅12个月，每席位每月120元。」

首次工具调用漏掉部分材料字段，验收脚本因总额未得到 7200.00 判为失败。
补充工具参数 schema 的字段定义后，第二次完整提取七项材料，
引用 SW-1、SW-2，由代码得到 7200.00 元。
本机脱敏结果在 data/procurement-acceptance/model-natural-language.json。
此样例只证明一次真实工具调用链，其他表达和完整软件补件流程继续验收。
