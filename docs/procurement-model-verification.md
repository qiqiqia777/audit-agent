# 采购模型审查阶段验证

2026-11-15，Windows、Python 3.12。

采购入口现已调用 MiniHermes 的 run_loop 和采购专用 ToolRegistry。工具仅返回后端绑定的当前申请、
版本化制度与本部门同类已办结案例。模型提交结构化材料、逐字段原文摘录及引用编号，
后端校验引用和原文存在性，再运行确定性规则重算费用。负责人核对建议并最终决定与发信。

SQLite 保存原邮件和审查任务。模型调用不持有数据库写事务，晚到结果与当前申请版本不符时丢弃。
审查完成会更新申请版本，旧表单不得批准模型运行后才更新的材料。
生产收信和页面要求当前版本审查成功；低层存储接口保留离线兼容选项。

## 真实模型验收

复用原邮箱工程已配置的 glm-4.5-air，通过既有 OpenAI 兼容适配调用，材料全部虚构。
输入为「申请订阅设计软件用于出图，需要5个席位，订阅12个月，每席位每月120元。」

首次工具调用漏掉部分材料字段，验收脚本因总额未得到 7200.00 判为失败。
补充工具参数 schema 的字段定义后，第二次完整提取七项材料，
引用 SW-1、SW-2，由代码得到 7200.00 元。
本机脱敏结果在 data/procurement-acceptance/model-natural-language.json。
此样例只证明一次真实工具调用链，其他表达和完整软件补件流程继续验收。

## 同一真实软件样例的修复与续办

在 data/procurement-acceptance/software-bulk-20261115/evidence.json 保存脱敏结果。
该样例复用了已发送的第一封申请，限定最近 30 个 UID，先取邮件头匹配唯一样例，再读取匹配正文。
测试匹配时统一了邮件传输中的换行表示，避免正文格式变化导致样例被漏掉。

1. 真实模型识别 120 元/月缺少报价口径，页面确认补件后在真实邮箱收到补件请求。
2. 员工在原会话回复「每席位每月120元」，接回同一申请，真实模型与代码得到 7200.00 元。
3. 员工再回复「改成8席」。初次模型审查错误回退到 5 席，脚本因未得到 11520.00 而失败。
4. 新增后端 confirmed_materials 约束。模型不得遗漏或改写从最新原文按规则核对的字段。
   保留原失败审查记录，用重新审查入口生成新版任务。真实模型修正后代码得到 11520.00 元。
5. 针对原 7200 元页面版本提交批准，返回 409；数据库中没有决定，也没有产生结果发信。
6. 新页面展示 5→8 席、7200.00→11520.00 元，确认批准后，在真实收件箱按发件人、唯一样例与批准正文核对到结果通知。

此验收使用真实 IMAP、SMTP、glm-4.5-air 和 HTTP 审批表单；浏览器人工交互仍未验证。
新增回归验证模型错误回退时工具拒绝提交并可修正重试，另验证版本差异相对于上次已完成审查，
避免中间规则计算结果掩盖 5→8 的真实材料变更。
