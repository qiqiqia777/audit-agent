# 采购审计 Agent 优化方案

目标是让 Agent 在证据不足时完成材料登记、指出具体疑问，并让申请停在待澄清状态。以 2026-11-17 的真实模型评测为基线，使用现有 runner 保存逐题结果、工具轨迹和业务状态。

## 第一轮 P0 · 报价歧义

三道题均为 5 席、12 个月，其他材料齐全。每题各跑 3 次，沿用原题和原评分规则。

| 报价输入 | 原整题成绩 | 预期提交及业务结果 |
|---|---|---|
| 120 元/月，未说明覆盖范围 | 0/3 | 保留金额 120、月付、5 席及 12 个月，省略 price_basis。提交成功，总额为空，状态为 needs_clarification，只问该报价覆盖一席还是全部五席 |
| 明确每席每月 120 元 | 3/3 | 提交 per_seat，总额 7200 元，进入 ready_for_review，无补件问题 |
| 明确全部五席每月共 120 元 | 3/3 | 提交 all_seats，总额 1440 元，进入 ready_for_review，无补件问题 |

1. **先复核基线。** 从已有 9 份轨迹提取首次提交的字段和引文，对照最终数据库状态及摘要。沿用原整题判定，另记首次提交是否正确，以便识别工具反馈后的纠正。
2. **只改提取指令。** 现有提示词已经要求省略歧义字段。把规则写成可执行判断：分别找支持金额、周期、覆盖范围的原文。“元/月”支持月付；“申请五席”支持数量。只有原文把报价明确关联到单席或全部席位时才填覆盖范围，否则提交其余已知字段并说明待确认事项。示例采用与评测题不同的金额和措辞。
3. **运行真实 Agent。** 固定模型 glm-4.5-air、采购制度、题目、评分版本和运行参数，每次使用独立数据库。逐次记录首次提交、工具反馈、最终有效提交、业务状态和负责人看到的建议。若摘要要求澄清但系统算出总额，或 Agent 重试耗尽、审查失败，均记录为失败。
4. **再单独加后端证据校验。** 对已提交的 price_basis 核对引文是否支持其覆盖范围。引文只证明周期或与所选范围冲突时，拒绝该字段并返回具体反馈，允许 Agent 省略无依据字段后重新提交。用基线里真实出现过的错误参数回放验证拦截，再用真实 Agent 重跑同三题各 3 次。工具回放和真实运行分别报告。

本轮目标是歧义题 3/3 正确停在待澄清，两道正常题分别保持 3/3。另列首次主动省略、工具拒绝后改正、最终仍失败的次数。未达目标时保留失败轨迹，先确定问题出在提取、反馈还是最终写入，再决定下一步。三次重复只描述本组表现。

## 后续顺序

| 顺序 | 修改内容 | 验收场景与观察点 |
|---|---|---|
| P0 第二轮 · 建议与业务状态一致 | 让 submit_review 返回实际状态、总额与待确认问题。检查负责人页面读取哪个摘要，并让实际展示和保存的建议依据同一业务结果生成 | 10 个月按季计费题。后端已正确保留季度周期、留空总额；负责人读到的建议还须明确询问不足整季的实际收费方式。用 12 个月整季度题检查是否新增多余追问 |
| P1 第三轮 · 工具提交可靠性 | 先明确金额字符串格式及正确示例，保留后端数值核验。另一步处理参数 JSON 解析失败，提供有上限的纠正机会，保存失败参数和每次反馈，核查重复提交 | 季度报价题检查能否把“120 元”规范为金额字符串；连续修改题检查解析失败后是否完成有效审查。分别报告首提成功、纠正成功和耗尽次数，数据库已有金额时仍须核对审查任务状态 |
| P1 第四轮 · 多轮材料提取 | 每轮按字段核对最新员工原文与旧材料，应用明确修改，保留其余已有依据的事实 | 缺用途题只追问用途；收到“补充 12 个月”后解除期限缺项；5→8→6 席逐阶段核对材料和总额，中间阶段失败要保留 |
| P2 第五轮 · 引文质量 | 将规范化字段值与逐字原文引文分开。需要多段证据时分别记录来源和片段 | 抽查月付和改席位题的提交，逐段定位到对应来信，检查内部枚举、跨邮件拼接及旧材料误引 |
| P2 第六轮 · 评分校准 | 将业务状态、执行过程、建议质量分别判定。用人工确认的正确、错误和边界样本校准，记录规则版本，再统一重评旧轨迹 | 用“出图／用于出图”检查同义误判，用不足整季度题检查建议质量漏判。保留原始分数，单列重评分数和判定理由 |

每轮交付一张逐题前后对照表，附代表性失败的首次工具参数、工具反馈、最终业务状态与建议原文。评分规则若有修订，同版规则须同时用于旧轨迹和新轨迹。
